# SplitEase – Group Expense Sharing Application

SplitEase is a modern, responsive, full-stack group expense sharing web application built with the **MERN** stack (MongoDB, Express.js, React with Vite & JavaScript, Node.js) and styled with **Tailwind CSS**.

SplitEase allows friends, roommates, and travel groups to create shared spaces, invite registered users, track equal and custom unequal shared expenses, calculate net balances dynamically, and generate optimal debt settlement recommendations using a greedy debt simplification algorithm.

---

## 🚀 Key Features

1. **Authentication & Authorization**
   - JWT-based authentication with secure password hashing via `bcryptjs`.
   - Protected client-side routes and server-side middleware verification.
   - User registration (Name, Email, Password, Confirm Password) and Login.
   - Profile management with name updates and secure password changes.
   - User security: Passwords and hashes are strictly excluded from all API responses.

2. **Dashboard**
   - Real-time financial summary calculated directly from live database records:
     - **You are owed**: Total amount other members owe you across all groups.
     - **You owe**: Total amount you need to pay across all groups.
     - **Active Groups**: Number of groups you participate in.
   - Recent expenses feed with details on group, payer, date, and your individual share.
   - Actionable settlement alerts for pending confirmations.
   - Dynamic notification banner for pending group invitations.

3. **Group Management**
   - Create groups with custom names and descriptions.
   - Automatic creator assignment as the group's first member.
   - Real-time group financial overview (total spend, personal net balance, member count).
   - Dedicated tabs for Expenses, Balances, Settlements, and Members.

4. **In-App Invitation System**
   - Search registered users by name or email, or invite directly via email.
   - Prevents duplicate pending invitations and invitations to existing group members.
   - Recipient sees invitations on their dedicated **Invitations** page with the inviter's name and group description.
   - **Accept**: Adds user to group members and makes it visible in *My Groups*.
   - **Reject**: Updates status to rejected without adding the user.
   - Zero external email services or WebSockets required.

5. **Expense Management & Flexible Splitting**
   - Any group member can add expenses.
   - Supports:
     - **Equal Split**: Evenly divides the amount among selected participants with automatic 1-cent remainder distribution to ensure zero rounding loss.
     - **Custom Unequal Split**: Exact amounts per participant with a real-time validation indicator ensuring the sum equals the total amount.
   - Member selection: Filter which members participate in each expense.
   - Authorization: Group members can view expenses; expense creators and payers can edit or delete their expenses.

6. **Core Feature: Dynamic Balance Calculation**
   - Balances are computed on the fly from actual expense records and confirmed settlements:
     $$\text{Net Balance} = (\text{Total Paid} - \text{Total Share}) + (\text{Confirmed Settlements Paid} - \text{Confirmed Settlements Received})$$
   - Positive balance ($+$): User is owed money.
   - Negative balance ($-$): User owes money.
   - **Conservation of Debt**: The sum of all member balances in any group always equals $\text{₹}0.00$.

7. **Core Feature: Simplified Settlement Algorithm (Greedy)**
   - Reusable algorithm located in `server/utils/settlementAlgorithm.js`:
     1. Separates members into **Creditors** (balance $> 0$) and **Debtors** (balance $< 0$).
     2. Sorts both pools descending by magnitude.
     3. Matches the largest debtor with the largest creditor.
     4. Transfers $\min(\text{debtor}, \text{creditor})$ and updates balances.
     5. Repeats until all balances are settled ($0.00$).
   - Safely operates on integer cents/paise to avoid IEEE 754 floating-point inaccuracies.
   - Minimizes transactions (at most $N - 1$ payments) and eliminates circular debt.

8. **Settlement Management Workflow**
   - Displays suggested transactions generated by the algorithm.
   - One-click **Settle Up** to record off-app payments (UPI, GPay, cash).
   - Multi-stage confirmation:
     - `pending`: Proposed settlement.
     - `awaiting_confirmation`: Payer marks the payment as sent.
     - `completed`: Receiver confirms receipt; group balances automatically update.
   - Security: Only the recipient can confirm receipt; unauthorized users are blocked with 403 Forbidden.

## 🛠️ Technology Stack

- **Frontend**: React 18, Vite, JavaScript (No TypeScript)
- **Styling**: Tailwind CSS
- **Routing**: React Router DOM (v6)
- **Icons**: Lucide React
- **HTTP Client**: Axios with JWT interceptors
- **Backend**: Node.js & Express.js (ES Modules)
- **Database**: MongoDB with Mongoose ODM
- **Authentication**: JSON Web Tokens (`jsonwebtoken`) & `bcryptjs`
- **Testing**: Node.js Native Test Runner (`node --test`)

## ⚙️ Environment Variables

### Backend (`server/.env`)
Create a file named `.env` inside the `server/` folder:

```env
PORT=5000
NODE_ENV=development
MONGODB_URI=mongodb://127.0.0.1:27017/splitease
JWT_SECRET=your_secure_jwt_secret_key_change_in_production
```

For **MongoDB Atlas**, set `MONGODB_URI` to your Atlas connection string:
```env
MONGODB_URI=mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/splitease?retryWrites=true&w=majority
```

### Frontend (`client/.env`)
Optional. Vite proxies `/api` requests to `http://localhost:5000` automatically during development.

## 🏃 Getting Started (Local Setup)

### Prerequisites
- Node.js (v18 or higher recommended)
- MongoDB running locally or a free MongoDB Atlas connection string

### 1. Clone the repository
```bash
git clone <repo-url>
cd SplitEase
```

### 2. Install Dependencies
```bash
# Install server dependencies
cd server
npm install

# Install client dependencies
cd ../client
npm install
```

### 3. Run Backend Server
```bash
cd server
npm run dev
```
The server will start at `http://localhost:5000`.

### 4. Run Frontend Development Server
In a separate terminal window:
```bash
cd client
npm run dev
```
Open `http://localhost:5173` in your browser.

## 📡 REST API Reference

### Authentication (`/api/auth`)
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| POST | `/api/auth/register` | Register a new user | No |
| POST | `/api/auth/login` | Login and obtain JWT token | No |
| GET | `/api/auth/me` | Get current user profile | Yes |
| PUT | `/api/auth/profile` | Update user name | Yes |
| PUT | `/api/auth/change-password` | Update account password | Yes |
| GET | `/api/auth/users/search?q=...` | Search registered users by email/name | Yes |

### Groups (`/api/groups`)
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| POST | `/api/groups` | Create a new group (creator is first member) | Yes |
| GET | `/api/groups` | List all groups user participates in | Yes |
| GET | `/api/groups/:groupId` | Get group details, expenses, balances & suggested settlements | Yes (Member) |
| POST | `/api/groups/:groupId/expenses` | Add an expense to group (equal or custom split) | Yes (Member) |
| POST | `/api/groups/:groupId/settlements`| Record a settlement between members | Yes (Member) |

### Invitations (`/api/invitations`)
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| POST | `/api/invitations` | Invite a registered user by email | Yes (Member) |
| GET | `/api/invitations` | Get current user's pending invitations | Yes |
| PUT | `/api/invitations/:id/accept` | Accept invitation and join group | Yes (Recipient) |
| PUT | `/api/invitations/:id/reject` | Decline invitation | Yes (Recipient) |

### Expenses (`/api/expenses`)
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| PUT | `/api/expenses/:expenseId` | Update an expense | Yes (Owner/Payer) |
| DELETE | `/api/expenses/:expenseId` | Delete an expense | Yes (Owner/Payer) |

### Settlements (`/api/settlements`)
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| PUT | `/api/settlements/:settlementId/mark-paid` | Payer marks settlement as paid | Yes (Payer) |
| PUT | `/api/settlements/:settlementId/confirm` | Receiver confirms receipt (`completed`) | Yes (Receiver) |
| DELETE | `/api/settlements/:settlementId` | Cancel a settlement | Yes (Participant) |

### Dashboard (`/api/dashboard`)
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| GET | `/api/dashboard` | Get user financial summary, balances & recent activity | Yes |

## 🚢 Production Deployment

### 1. Build Frontend
```bash
cd client
npm run build
```
Generates production-optimized static assets in `client/dist`.

### 2. Deploy Backend & Database
- Host MongoDB database on **MongoDB Atlas** (M0 Free Tier).
- Deploy the `server/` directory on platforms like **Render**, **Railway**, or **Heroku**.
- Set the following environment variables in your hosting dashboard:
  - `PORT=5000`
  - `NODE_ENV=production`
  - `MONGODB_URI=your_mongodb_atlas_connection_string`
  - `JWT_SECRET=your_production_secret`
- Deploy the `client/` frontend on **Vercel** or **Netlify** with `VITE_API_URL` pointing to your deployed backend API URL.
